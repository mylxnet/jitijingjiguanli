# 13 · 历年欠款分年度管理与整额核销（v0.13）

> 关联文档：docs/09-parties-design.md（应收/往来模型）、docs/12-onboarding-import-design.md（引导页）。
> 生效版本：v0.13.0（2026-09-10）。数据模型基于既有 receivable（单位 × 年度 × 类别 一张应收单）**不变**。

## 背景与场景

集体经济往来中常见"某流转企业多年拖欠土地流转费"。业务诉求：

1. 建账初期就能把**往年欠款按年度补录**（如 2024、2025 各欠一笔），此后逐年展示各自收欠进度；
2. "土地流转费收入 / 流转管理费"页能**按真实存在的欠款年份查看**，而不是写死 `当前年~建账年`；
3. 收款时**一笔钱可以自动抵多年欠款**，按"先还早年份"的顺序摊分，不必逐张单手动分拆；
4. 单位列表能看到**欠款合计**，一眼掌握催收对象。

## 一、登记欠款（应收流转费 / 管理费 / 投资收益页）

### 1.1 入口
三个应收列表页标题栏「导出」左侧新增 **「登记欠款」**。单位预览弹窗不承担登记职责。

### 1.2 表单
| 字段 | 说明 |
|---|---|
| 单位 | 原生下拉，**只列适用于本页类型的单位**（流转费/管理费 → 流转企业；投资收益 → 投资/再投资单位）。类别由页面锁定，无需手选。 |
| 年度 | 原生下拉，**不含本年度、往前 5 年**（2026 → 2025…2021）。欠款年份落在更早可后续放开。 |
| 金额 | 选中单位后**自动带出该单位本类应收标准**（流转费/管理费/年收益，取 `expected*Cents`），可修改；无标准则留空。 |
| 事由 | 留空自动生成 `{year}年度{类别}`，如 `2024年度土地流转费`。 |

### 1.3 防重（后端为准）
- 单笔登记 `POST /api/receivables` 对 **rent / service** 做"同单位+同类别+同年度"唯一校验，重复返回 `DUPLICATE_RECEIVABLE`（与批量计提语义一致）；
- `dividend / other` 等非年度性类别允许多笔，不误伤；
- 作废采用物理删除（既有约定），作废后可重录。

### 1.4 年度维度
- 后端 `recv_year` 支持任意历史年（0 = 当年）；登记历史欠款直接传 `recvYear`。

## 二、展示：按年度看历史欠款

### 2.1 "土地流转费收入 / 流转管理费"页年份下拉 = 数据驱动
- 年份集合 = **当前年 ∪ 该类别应收单实际年度 ∪ 该类别支出流水年度**，倒序；不再有 `START_YEAR=2026` 下限；
- 首次进入若当前年无该类数据，自动聚焦最近有数据的欠款年份；
- 统计口径沿用单年应收单语义：选中 2024 看 2024 欠款的应收/已收/未收；现在补收 2024 的款记在该年度单上。

## 三、收款核销（两种入口）

| 入口 | 语义 | 接口 |
|---|---|---|
| 应收列表某单「收缴」 | **只结清这一张单**，金额不能超过该单未收 | `POST /api/receivables/{id}/receipts`（单张，既有） |
| 快速记账「收到土地流转费/管理费/收益」 | **整额收款**，自动跨单摊分 | `POST /api/party-collect`（v0.13 新增） |

### 3.1 整额跨单核销规则（`/api/party-collect`）
请求：`{partyId, recvKind, amountCents, receiptDate?, note?}`，恒为现金方式、入账科目自动定位/创建该单位同名收入二级（同单张核销）。

单事务内执行：
1. 取该单位该类 **status='open'** 的应收单，按 `recv_year ASC, id ASC` 排序（**最早年度优先**）；
2. 校验 `amountCents ≤ Σ未收`，超过返回 `COLLECT_OVER_TOTAL`（提示待收合计）；无可核销单返回 `COLLECT_NO_OPEN`；
3. 逐单摊分：每张核销 `min(剩余, 该单未收)`，收满置 `closed`，否则保持 `open`；
4. 每摊到一单生成**一条核销记录 + 一笔银行收入流水**（receipt↔txn 一对一，单笔可单独作废并连带作废对应流水）。

示例（2024、2025 各欠 3000）：
| 收款 | 结果 |
|---|---|
| 2000 | 冲 2024 → 2024 剩 1000 |
| 3000 | 先补清 2024(1000)，再冲 2025(2000) → 2025 剩 1000（跨年摊分） |
| 1000 | 结清 2025 |

### 3.2 为什么现金流水按"每单一条"
保证 receipt 与其银行收入流水一对一，作废任意单张摊分核销时只回退该单金额与该笔流水，其它摊分不受影响（沿用单张核销的既有不变式）。若一笔整额收款摊 2 单，则产生 2 条收入流水，金额合计等于收款额。

## 四、计提标准打通（连带修复）

| 项 | 决策 |
|---|---|
| 标准表唯一数据源 | 年度计提预览/结转统一读取 **`recv_standard`**（不再读单位表旧 `expected_*` 字段）。 |
| 迁移 014 | `recv_standard.recv_kind` CHECK 加入 **service**（原仅 rent/dividend/other，导致管理费标准无法保存、向导管理费步恒空）。重建表保留数据。 |
| 引导页联动 | 更新流转企业预期流转费/管理费（`PUT /api/parties/:id`，flow 且 >0）时**自动 upsert 标准**（rent/service），建账即可在年度计提预览/结转中使用。 |
| 结转放行 | `AccrueFromStandards` / 结转接口放行 service（rent/service → flow，dividend → invest）。 |
| 预览修复 | `GET /api/recv-standards/preview` 改按启用标准 + 单位类型匹配出清单（此前读旧字段导致预览恒空）。 |

## 五、单位列表欠款合计

"是否有合同"与"备注"之间新增 **欠款合计** 列：显示后端 `outstandingCents`（= 该单位所有 `open` 应收单未收之和），大于 0 红色加粗；CSV 导出同步含该列。

## 验收要点

- [x] 应收三页可登记欠款，年度下拉为不含本年的前 5 年；金额默认带标准且可改
- [x] 同单位同类别同年度重复登记被拦截（前端提示 + 后端 `DUPLICATE_RECEIVABLE`）
- [x] 土地流转费收入/管理费年份下拉覆盖真实欠款年份（含历史年），并能看到各年收欠
- [x] 整额收款按最早年度优先自动摊分；超待收合计被拒并提示金额；无可核销被拒
- [x] 单张「收缴」仍只核销指定单，两语义互不干扰
- [x] 计提标准支持 service；引导页填的费用自动进标准；年度计提预览不再为空
- [x] 单位列表欠款合计列 + 导出列
- [x] 后端 `go test ./internal/receivable/` 全绿（新增防重/标准同步/整额跨单测试）
