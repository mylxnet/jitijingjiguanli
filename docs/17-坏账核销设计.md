# 17 · 坏账核销设计

> 状态：已实现（未发版）｜ 关联：docs/09-parties-design.md（应收/往来模型）、docs/13-receivable-yearly-debt-design.md（分年度欠款与整额核销）、`.trae/rules/project_rules.md`

## 1. 背景与目标

集体经济往来中，部分应收款项因对方无力/无法支付而成为**坏账**。这类款收不回来，但会一直挂在"待收"里，
导致欠款合计虚高、催收清单失真、年末无法结平。

目标：提供一种**有记录、有原因、可撤销**的坏账处理方式，把指定应收单的**剩余待收**清零，且
**不影响银行存款、科目余额与收支汇总**（因为确实没有钱进来）。

## 2. 现状与"为什么现在清不掉"

现有模型（基于 `receivable` + `receipt`）：

- `receivable`：`amount_cents` + `status`（`open` / `closed`）；
- `receipt`：核销记录，`method` 目前只有 `cash`（现金收款，生成一条银行收入流水）与
  `offset`（抵销，关联一条既有支出流水，不产生现金流水）；
- 派生口径（不入库）：`已核销 PaidCents` = 该单全部 `status='normal'` 的 receipt 合计；
  `待收 OutstandingCents` = `amount - paid`；`paid == amount` 时自动置 `closed`；
- 往来单位"欠款合计"只统计 `status='open'` 的应收单。

现有唯一能"抹掉"应收的入口是**作废应收单**（`PUT /api/receivables/:id/void`），但它够不着坏账场景：

| 限制 | 后果 |
|---|---|
| 只允许 `status='open'` 且 `PaidCents == 0` | 已收过一部分的单，剩余变坏账 → 清不掉 |
| 直接 `DELETE` 掉整行 | 历史全没、不留痕、不可撤销 |
| 语义是"作废/重结" | 不等于"坏账核销"，账务含义不同 |

**结论：坏账现无处理能力，需要新增机制。**

## 3. 方案决策（用户逐项确认）

| 议题 | 结论 |
|---|---|
| 实现方式 | 新增第三种核销方式 `writeoff`（不删单，走核销记录） |
| 账目影响 | **只清应收、不动账**：不生成任何流水；银行/科目/收支汇总全不变 |
| 核销粒度 | **整单清零**：一键把该单**剩余待收**全额转坏账，前端不可改额（后端强制取待收） |
| 展示口径 | **三栏**：已收（`cash`+`offset`） / 坏账（`writeoff`） / 待收 |
| 可逆性 | **允许撤销**：复用现有「作废核销」，`closed → open`、待收恢复 |
| 入口 | **设置页**独立功能项 → 弹窗核销；往来页核销弹窗**保持现状**（仍只有 现金/抵销） |
| 选单方式 | 弹窗内**列表 + 筛选**（往来单位 / 年度 / 应收类别） |
| **核销年度限制** | 仅可核销**本年度以前**的应收（`recvYear < 当前年`）或**未填年度**（`recvYear = 0`）；本年度及以后一律拒绝，错误码 `BAD_DEBT_YEAR_NOT_ALLOWED` |
| **正常页面可见性** | 一条应收单出现在正常页面（**明细与合计同一集合**）的条件：**非坏账单**，**或**坏账单但**实际已收（现金）> 0**。部分坏账（有真金白银进来）→ 显示并标「坏账」，按 应收/已收/坏账/未收 四栏呈现；**全额坏账（一分没收）→ 正常页面完全剔除**，只在坏账清单页归档。故「合计 = 明细之和」 |
| **查看入口** | 应收页「坏账」统计卡 → 跳转**坏账清单页**（正常路由页面，非弹窗），列出**全部**坏账单（含全额坏账）与详情 |
| **撤销入口** | 坏账清单页内「撤销坏账」（因坏账已从正常页面剔除，撤销入口随之迁移到该页，否则不可达） |

语义定义：坏账核销 = 一条 `receipt(method='writeoff', txn_id=NULL, note=原因)`；
`待收` 随之减到 0 → 应收单自动 `closed`。**不生成 txn，不碰任何账目。**

## 4. 数据层（唯一 schema 改动）

- 新增迁移 `018`：重建 `receipt` 表，把 `method` 的 CHECK 从 `('cash','offset')` 放宽为
  `('cash','offset','writeoff')`；沿用迁移 `012_receivable_kind.sql` 的
  `PRAGMA defer_foreign_keys=ON` 重建法（保留原 id，`receipt` 外键约束不受影响）。
- `receivable` 结构**不动**，继续使用 `open` / `closed` 两态。

## 5. 后端改动

| 位置 | 改动 |
|---|---|
| `internal/receivable/model.go` · `CreateReceiptRequest` | `Method` 放开为 `oneof=cash offset writeoff` |
| `internal/receivable/handler.go` · `CreateReceipt` | 新增 `case "writeoff"`：**不需要** `txnId`、**不需要**科目；**后端强制 `amount = 剩余待收`**（忽略前端传值，防多写）；**先校验年度限制**：`recvYear != 0 && recvYear >= 当前年` → `BAD_DEBT_YEAR_NOT_ALLOWED`；`note`（坏账原因）必填，否则 `BAD_DEBT_NOTE_REQUIRED` |
| `internal/receivable/repo.go` · 新增 `CreateWriteoffReceipt` | 与 `CreateOffsetReceipt` 同构：单事务写 `receipt(method='writeoff', txn_id=NULL)`；`paid+amount==amount` → `closed`；**不写 txn** |
| 撤销 | **零开发**：复用 `VoidReceipt`（它只对 `cash` 连带作废流水，`writeoff` 天然不碰流水），自动 `closed→open`、待收恢复 |
| 留痕 | 复用 `change_log`（核销创建/作废 + 应收状态变更） |
| 口径查询 | `ListReceivables`、`GetReceivableDetail` 增加 `writeoff = SUM(method='writeoff' AND status='normal')`。模型新增 4 个字段：`writeoffCents`（坏账合计）、`writeoffDate`（最近一笔坏账日期）、`writeoffNote`（坏账原因）、`writeoffReceiptId`（坏账核销记录 id，供清单页撤销）。**`sumPaidTx` 保持"全部 normal"不变**，状态机逻辑零风险 |
| 不改 | `ListParties` 的欠款合计只算 `status='open'`，坏账后单子已 `closed`，自动排除，无需改动 |

状态机不变式（沿用现有）：
- `paid(全部 normal 核销) == amount` → `closed`；否则 `open`；
- 作废任一核销后重新汇总，未结清则退回 `open`。

## 7. 影响面（结论）

坏账**不生成任何流水**，因此：

- **不变**：银行存款、科目余额、收支汇总、导出结果；
- **变化**：应收单 `待收` 减少、往来单位`欠款合计` 减少（该单 `closed` 后被排除）。

这与"坏账收不到钱"的现实一致。往来页的日常核销动线不受影响；坏账归入设置页，属低频且"危险"操作，
与日常动线分离，误点风险更低。

## 8. 边界与测试要点

将来在 **WSL 真实环境**执行 `cd /mnt/e/traework/jizhang/server && go test ./...`，新增用例进 `receivable` 包：

| 场景 | 预期 |
|---|---|
| 越权（他人组织应收单） | 404 |
| 已结清单再核销 | `RECEIVABLE_CLOSED` |
| 重复 / 并发双击 | 幂等 / 单次生效 |
| 部分已收后坏账 | 坏账额 = **剩余待收**，非整单金额 |
| 撤销坏账核销 | `closed → open`，待收恢复 |
| 撤销后再核销 | 可重现，状态正确 |
| 缺原因 | `BAD_DEBT_NOTE_REQUIRED` |
| 核销本年度应收 | `BAD_DEBT_YEAR_NOT_ALLOWED`（往年 / 未填年度正常放行） |
| 坏账后正常页面 | 部分坏账（现金已收>0）→ 正常页面**显示并标「坏账」**（应收/已收/坏账/未收）；全额坏账（现金已收=0）→ 正常页面**完全剔除**。两者在坏账清单页均可查、可撤销 |
