# 20 · 备份设计（含下载到本地）

> 对应 [03-design.md §5.6](03-design.md) 的一致性备份能力（F7/R3）。本文档如实描述当前实现的存储位置、生命周期、保留策略与安全边界；**「下载到本地」为 v0.20 新增**，是全链路最后一个闭环。

---

## 一、目标与范围

- 提供 SQLite 数据库的一致性备份与恢复，防止数据丢失。
- 备份产物可**下载到本地**，用于离线归档 / 异地备份 / 迁移取回。
- 与数据库、合同文件在内的全部业务数据保持一致（单文件即全部）。

## 二、备份存储位置

| 项 | 值 |
|---|---|
| 备份目录（Runtime 配置） | `cfg.BackupDir`，默认 `./backups` |
| 环境变量 | `APP_BACKUP_DIR` |
| 备份文件名 | `jz-backup-YYYYMMDD-HHMMSS.db`（东八区 `Asia/Shanghai`） |
| 保留份数 | `APP_KEEP_BACKUP`，默认 **30** |
| 数据目录 | `cfg.DataDir`（`DATA_DIR`），数据库文件 `jititaizhang.db` |

> 设计建议：备份目录**与数据目录分盘/分离**（03-design R3/F7），避免单点故障同时毁掉数据与备份。

## 三、备份方式（一致性快照）

实现 [backup.go `Create`](file:///e:/traework/jizhang/server/internal/backup/backup.go#L77-L100)：

```sql
VACUUM INTO '<备份文件路径>'
```

- `VACUUM INTO` 生成**静态一致快照**，天然规避运行期 WAL 不一致问题；
- 快照为独立 `.db` 文件，**与数据同库同版本**，可直接覆盖恢复。

### 合同文件内含说明
合同原文件以 BLOB 存于 `contract.file_data` 字段（随数据库存储，非凡文件系统路径）。因此**一致性备份 = 业务数据 + 全部合同文件**，一份 `.db` 即全量，无需对合同单独额外备份；恢复该备份即恢复合同文件。

## 四、生命周期与 API

路由均在 `authed`（登录）组：[main.go 备份路由块](file:///e:/traework/jizhang/server/cmd/server/main.go#L174-L241)

| 动作 | 接口 | 说明 |
|---|---|---|
| 列表 | `GET /api/backups` | 按时间倒序（最新在前） |
| 创建 | `POST /api/backups` | 立即生成一份快照并触发保留清理 |
| **下载** | `GET /api/backups/:id/download` | **v0.20 新增**，流式下发 `.db` |
| 恢复 | `POST /api/backups/:id/restore` | 覆盖当前库，恢复后强制重新登录 |
| 删除 | `DELETE /api/backups/:id` | 最新一份受保护不可删 |

### 下载实现要点（v0.20 新增）
后端 [下载接口](file:///e:/traework/jizhang/server/cmd/server/main.go#L217-L227)：
- `id` 经 `filepath.Base` 消毒，防路径穿越；
- 校验备份存在且非目录，否则 404；
- `c.FileAttachment(backupPath, id)` → 自动写 `Content-Disposition: attachment`，**流式**发送，不占内存。

前端 [http.ts `downloadFile`](file:///e:/traework/jizhang/web/src/lib/http.ts#L88-L112)：以 `credentials:'include'` 拉 blob，从 `Content-Disposition` 解析文件名；[SettingsPage `downloadBackup`](file:///e:/traework/jizhang/web/src/features/settings/SettingsPage.vue#L349-L363) 用 `URL.createObjectURL` + 隐性 `<a download>` 触发浏览器保存。

## 五、保留策略与最新保护

- 每次 `Create` 后执行 `prune()`：超出 `keep` 份删除最旧（用户版默认 30，每日一次场景约近 1 个月）；
- `DeleteFile`：`items[0]`（最新一份）**不可删除**，返回 `ErrLatestProtected`，前端对应禁用删除按钮；
- **下载不受该保护限制**：任何备份均可下载。

## 六、自动备份

`runDailyBackup` 于每日 **03:00**（本机时区）自动执行一次 `repo.Create()`（[main.go](file:///e:/traework/jizhang/server/cmd/server/main.go#L335-L356)），失败仅记录日志不中断服务。

## 七、安全边界

- 所有备份接口要求登录（`authed`）；
- 路径参数一律 `filepath.Base` + `os.Stat` 存在性校验；
- 恢复成功后清空会话 Cookie（旧会话属于恢复前库）。

## 八、配置项与 Docker 卷映射

| 配置 | 环境变量 | 默认 | Docker |
|---|---|---|---|
| 数据库路径 | `DATA_DIR` | `./data` | `VOLUME ["/data"]` |
| 备份目录 | `APP_BACKUP_DIR` | `./backups` | `VOLUME ["/backups"]` |
| 保留份数 | `APP_KEEP_BACKUP` | `30` | — |

部署时 `-v <宿主目录>:/data -v <宿主备份目录>:/backups` 持久化；备份 `.db` 内含合同文件，随备份目录持久化。

## 九、验证结论（真实链路）

| 检查项 | 结果 |
|---|---|
| 下载接口 `GET /api/backups/:id/download` | `200` |
| 下载头 | `Content-Disposition: attachment; filename="jz-backup-….db"`、`application/octet-stream` |
| 二进制一致性 | 下载文件 SHA1 == 服务器备份文件 SHA1 |
| 前端「下载」按钮渲染 | 设置页备份行出现 |
| 前端点击 | 无失败提示，正常触发下载 |

## 十、已知限制 / 未覆盖

- v0.20 未对「恢复」做 UI 二次确认（恢复为破坏性操作，当前依赖前端确认弹窗）；
- 下载在浏览器被下载策略拦截时属环境限制，非本功能问题；
- 大体积备份走流式，不预载内存；未做断点续传。
