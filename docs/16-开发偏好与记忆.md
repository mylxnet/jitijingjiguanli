## 0. 最高优先级硬性规则（红线）

以下几条**优先级高于任何习惯与直觉**，与本文其他内容冲突时以本节为准：

1. **禁止擅自升版本号**。只有用户明确说"建立新版本"才允许升；递增规则为**次版本号 +1**（`0.15.0 → 0.16.0`）；版本号**单一来源**，禁止在别处写死；升版本的同时提交并推送。
2. **禁止擅自构建镜像**。只有用户明确说"打包镜像"或"生成镜像"才构建；一旦要构建，就是**构建 + 一并推送到镜像仓库**；不允许"只构建不推送"或"只推送不构建"。
3. **禁止擅自提交/推送**。未获明确指令不得 `git commit` / `git push`。
4. **禁止擅自扩大改动范围**。用户说"先帮我改 X"，就只改 X；发现别的问题只报告，不动手。
5. **破坏性操作必须先出清单等确认**：删除文件/目录、改数据结构、重置数据等，先列清单（含大小、用途、风险分类）并等用户确认，再执行。
6. **绝不删除数据与备份**：现行数据库、备份目录、迁移出的历史库一律不动。
7. **测试结论必须真实**：所有后端测试必须在**真实运行环境**（真实 HTTP + 真实数据库）跑通，禁止用 mock / 假数据自证"已通过"。
8. **测试环境在 WSL 里搭建与运行**，不在 Windows 宿主机上搭建或执行测试。
9. **额外数据不得混进代码**：测试产物、临时数据、调试转储、临时脚本**一律放进唯一的 `_scratch/` 目录**（已 gitignore），禁止散落在仓库各处。

## 1. 协作与沟通偏好

- **全程中文**，包括回答、方案、文档、代码注释、提交信息。
- **一次只问一个问题**，直到完全理解；不要一次抛出一堆问题。
- **提问必须带选项**，让用户点选而不是自由描述（能选就不要让用户打字）。
- **先复述理解，再动手**：动手前把"我的理解"说清楚，得到确认后才执行。
- **关键决策先出方案、不写代码**：涉及设计取舍时，先给方案供审阅，审阅通过再实现。
- **方案要落盘**：正式方案写成项目内文档（见 §8），不要只留在对话里。
- **不确定就说不确定**，不要编造；发现自己错了要**主动更正并致歉**（例：验证时 grep 未转义点号导致误报，应立刻用固定串复核并主动说明）。
- **汇报格式固定**：
  1. 改动清单（文件 + 一句话说明，带可点击的代码位置引用）
  2. **验证结果表格**（检查项 / 结果 / 证据）
  3. 遗留项与风险（含"与本次无关的既有失败"）
  4. 是否需要下一步（提交/打包/发布）
- **不要含糊结论**：能实测就实测（查库、跑接口、验镜像内容），不要写"应该没问题"。
- 用户用"**先…**"（如"先帮我改 X"）表示**只做这一步**，不要顺手做别的。

## 2. 指令词汇表（听到这些词才做对应动作）

| 用户说 | 才允许做 | 默认规则 |
|---|---|---|
| 「**建立新版本**」/「升级版本」 | 升版本号 | 次版本 +1；改唯一来源；同时提交推送代码仓库 |
| 「**打包镜像**」/「**生成镜像**」 | 构建并推送镜像 | **在本机 WSL 内构建**；构建 + 推仓库（`<版本>` + `latest`），缺一不可 |
| 「**验收**」/「**测试**」/「测一下」/「验证一下」 | 对**当前正在做的那一小节**做**全面测试** | 不得当成随口确认；见下方"全面测试"定义 |
| 「**完善方案与逻辑**」 | 沉淀设计文档 + 加固实现逻辑 | 补设计文档（背景/口径/交互/边界/验证记录）+ 复核实现漏洞并修复 |
| 「**定方案 / 不写代码**」 | 只出方案 | 不得改代码，只给方案待审阅 |
| 「**上传 / 推送**」 | 提交并推送到代码托管 | 只推当前已完成的工作 |
| 「**清理无用的文件**」 | 清理 | 先出分类清单（安全删 / 待定 / 保留 / 绝不动）并等确认 |

**「全面测试」的定义**（收到「验收/测试」时按此执行）：

1. 覆盖**正常路径 + 边界 + 异常**：空值、负数 / `NaN`、越权 / 未登录、重复提交、并发、超额等。
2. 后端在 **WSL 真实环境**执行（`go test ./...`），必要时**补测试用例**。
3. 前端无测试框架时，用**真实数据核对**（直接查库按规则算一遍，与界面口径逐步对照）。
4. 交付时给出**验证结果表**，并明确写出**未覆盖项与已知风险**。

## 3. 环境搭建约定

**通用规则**

- **主控台**：Windows + PowerShell。
  - 不支持 heredoc → 多行提交信息用 here-string（`@"..."@`）或写临时文件 `git commit -F`。
  - 不支持 `&&` 串联 → 用 `;` + `if ($LASTEXITCODE -eq 0)` 判断。
- **重活、容器、测试**：一律在 **WSL 发行版**内执行，路径用 `/mnt/<盘符>/...`。
  - **测试运行环境在 WSL 里搭建**，不在宿主机搭建/运行。
  - 通过 `wsl -- bash -lc '...'` 传多语句命令时，**外层引号容易被吞**（`syntax error near unexpected token`）→ 改为**写脚本文件再执行**。
- **容器构建**：推送到**阿里云个人版**仓库时**必须**加 `--provenance=false --sbom=false`，否则 BuildKit 会产出带 attestation 的 manifest list，仓库报 `unknown manifest class for application/vnd.oci.empty.v1+json`。
- **本地运行**：固定端口，数据目录用环境变量注入，不要把数据放在源码目录里。
- **本地构建链路**（单二进制内嵌前端）：前端构建 → 同步 `dist` 到后端静态目录 → `go build` → 重启进程 → 健康检查。
- **同步静态资源时要注意**：`robocopy /E` **不会清理**目标目录里的旧文件，多次构建会堆积历史 chunk；发现堆积应"**清空 + 重新同步**"（不要手工挑文件，因为前端是运行时按文件名动态加载 chunk 的）。`robocopy` 退出码 ≤7 视为成功。
- **目录隔离**：源码目录只放代码；测试产物、临时数据、调试转储、临时脚本一律放 **`_scratch/`**（并入 `.gitignore`），按用途分子目录。
- **重启进程要显式按进程名查杀**，且注意：跑服务的终端若被后续命令复用作掉，服务会掉线——重启后要复查健康状态。

**【本项目】具体值**

- WSL 发行版 `lxsyzd`；项目根映射为 `/mnt/e/traework/jizhang`。
- WSL 工具链：Go `1.27.0` 在 `/usr/local/go`、Node `v22.23.2` 在 `/usr/local/node`，均已软链到 `/usr/local/bin`（任何 shell 可直接调用）；`GOPROXY=https://goproxy.cn,direct`、`GOMODCACHE=/root/go/pkg/mod`。
- 环境重建脚本：`_scratch/tmp/install_go.sh`、`install_node.sh`、`link_toolchain.sh`；验收脚本 `_scratch/tmp/verify_env.sh`。
- 本地端口 `8080`；数据目录 `E:\traework\jizhang\data\`，备份 `data\backups\`。
- 构建链路：`cd web && npx vite build` → `robocopy web\dist server\cmd\server\web /E` → `cd server && go build -o bin/jititaizhang.exe ./cmd/server` → 重启 → `GET /api/health`。

## 4. 技术选型偏好

**通用规则**

- **后端**：Go 标准库为主 + **真实 SQLite**（纯 Go 驱动、无 CGO）；**单二进制内嵌前端**，便于单文件部署。
- **数据库迁移**：`NNN_描述.sql` 顺序编号、只增不改、`go:embed` 嵌入。
  - 修改 `CHECK` 约束等需**建新表 → 搬迁数据 → 删旧表 → 改名**，并迁移历史数据。
  - 新规则上线要**回填老数据**，避免老数据被新逻辑误判。
- **前端**：Vue 3 + Vite + TypeScript + Vant + Pinia。
- **目录结构遵循语言/框架官方惯例**，不自创结构：
  - Go：`cmd/`（可执行入口）、`internal/`（私有包）、模块根放 `go.mod`；
  - 前端：`src/` 下按 `features/`（业务域）+ `components/` + `lib/` + `types/`（+ `composables/`、`router/`、`styles/`）组织；
  - 后端测试与被测包放在一起（`*_test.go` 同目录）。
- **测试**：后端必须有真实链路测试（真实 HTTP + 真实数据库），覆盖新逻辑与回填迁移，**在 WSL 里跑**；前端无测试框架时用真实数据核对。
- **避免过度工程**：能用现有能力解决就不加重依赖；能复用现有接口就不加新接口。

**【本项目】具体值**

- 后端入口 `server/cmd/server/main.go`；业务包 `server/internal/{auth,backup,category,changelog,contract,export,fundmove,onboarding,platform,receivable,settings,summary,transaction}`。
- 迁移 `server/internal/platform/migrations/001~017_*.sql`（`go:embed migrations/*.sql`）。
- 前端 `web/src/`：`features/`（auth、category、contacts、flow、investment、onboarding、settings、summary、transaction）+ `components/` + `composables/` + `lib/` + `router/` + `styles/` + `types/`。
- 金额一律**以「分」存储**（`*Cents`），展示走 `formatFen`。

## 5. 设计风格偏好

- **双端布局**：桌面用左侧边栏导航（`SideNav`），移动用底部 tab 导航（`BottomNav`）；两端功能一致、信息密度适配。
- **弹窗规范**：统一走 `popupPos()`——**桌面居中弹窗**、**移动底部弹层**；不要两端都用底部弹层。
- **组件统一**：统一使用成熟组件库（Vant 的 popup / dialog / field / tabs / badge 等），不自造轮子。
- **金额口径**：以"分"存储，展示统一走格式化函数；页面之间口径必须一致（同一含义同一来源）。
- **表格**：固定表格布局 + 列宽控制，保证整齐；数字列右对齐，语义决定列对齐方式（如"欠款"按要求左对齐要照做）。
- **文案**：口语化、准确、无歧义；按钮用动词短语（"确定分配"），表头用业务名词（"已收收益"）；空态要有下一步引导（"请点击 XX 按钮…"）。
- **提醒类 UI**：像微信未读数那样，用**红底数字角标**（>99 显示 `99+`，为 0 隐藏），点击展开明细，明细每行可直达处理入口。
- **按类型差异化展示**：不同业务类型隐藏/显示不同列，不要"一刀切"显示所有字段。

## 6. 容错与数据安全机制

- **空值判定要严**：`blank(v) = !(Number(v) > 0)`——空、负数、`NaN` 一律视为"未填"，防止脏数据被当有效。
- **失败要留旧值**：请求失败不覆盖上一次结果，避免界面闪动/角标忽隐忽现。
- **并发要合并**：同一份数据被多个入口刷新时，用 `inflight` 复用同一请求，避免重复拉取。
- **前端不做权威判定**：关键状态以**服务端字段**为准（如"是否已建账"），不要依赖 localStorage；换浏览器/清缓存不应改变判断结果。
- **守卫要"宁可放行，不可误跳"**：鉴权/引导类判断在信息缺失或接口异常时应放行，避免把用户误踢到引导页。
- **防重与幂等**：唯一性校验（如"单位名 + 类型"、同类费用重复登记）；提供幂等接口（重复调用结果一致）。
- **二次确认 + 服务端再校验**：前端禁用按钮只是体验，服务端必须再校验一次（如"已支出完毕不可再记账"）。
- **越界校验**：金额不得超可用额度；不允许出现负余额等非法状态。
- **凭据只本机留存**：仓库地址/账号/密码写进**本机规则文件**（不入 git）；写密码时**用脚本从已有凭据处读出后直接落盘**，不要在对话/终端里回显；同时提醒用户定期更换。
- **发布前必查**：构建产物要核对**版本号**与**新功能特征串**，并核对远端镜像**清单类型与 digest**；同时确认**没有旧版本残留**（注意：用 `grep` 校验版本号时，`.` 要转义或用固定串匹配 `grep -F`，否则会误报）。

## 7. 部署与发布风格

**通用规则**

- **代码托管**：Gitee（`origin main`）；提交信息用中文，首行 `feat/fix/docs/refactor: 摘要`，正文列要点。
- **镜像构建位置**：**本机 WSL** 内构建（不在宿主机建镜像），构建后**立即推送**。
- **镜像仓库**：阿里云容器镜像服务（ACR）个人版；地址与凭据**只写在本机规则文件**。
- **标签策略**：同时推 `<版本号>` 与 `latest`；两标签必须**同一 digest**。
- **权限注意**：推送需登录；仓库若为公开则**拉取免登录**；凭据不要写进命令行（会留在 shell 历史），也不要外发。
- **目标机升级**：`docker compose pull` + `up -d`；注意**浮动标签 `latest` 不会因 `up -d` 自动更新**，必须先 `pull`；要可回滚就用固定版本号。
- **compose 文件**：镜像地址写注册表全路径；旧流程（手拷 tar / `docker load`）的注释要**同步更新**。
- **发布前置条件**：真实环境测试全绿 → 升版本号 → 提交推送 → 构建推送镜像 → 验证镜像内容。

**【本项目】具体值**

- 镜像：`registry.cn-hangzhou.aliyuncs.com/mylxnet/jitijingjiguanli`（公开仓库，拉取免登录），标签 `vX.Y.Z` + `latest`。
- 构建命令（WSL `lxsyzd`，项目根 `/mnt/e/traework/jizhang`）：
  ```bash
  docker login registry.cn-hangzhou.aliyuncs.com
  docker build --provenance=false --sbom=false -f deploy/Dockerfile.local \
    -t registry.cn-hangzhou.aliyuncs.com/mylxnet/jitijingjiguanli:<版本> \
    -t registry.cn-hangzhou.aliyuncs.com/mylxnet/jitijingjiguanli:latest .
  docker push registry.cn-hangzhou.aliyuncs.com/mylxnet/jitijingjiguanli:<版本>
  docker push registry.cn-hangzhou.aliyuncs.com/mylxnet/jitijingjiguanli:latest
  ```
- NAS 升级：`docker compose -f deploy/docker-compose.nas.yml pull && ... up -d`。

## 9. 交付与验收标准

一次任务"完成"必须同时满足：

## 附录 B：易踩的坑（血泪清单）

| 场景 | 坑 | 正确做法 |
|---|---|---|
| 推送镜像到 ACR | BuildKit 产出 attestation 清单，仓库报 `unknown manifest class` | 构建加 `--provenance=false --sbom=false` |
| `grep` 校验版本号 | `.` 是通配符，会把 `0,15,0` 也算命中，导致误报 | 用 `grep -F` 固定串，或转义 `\.` |
| `robocopy /E` 同步静态 | 不清理目标目录，旧 chunk 越堆越多（曾堆到 195 个） | 先清空再同步 |
| PowerShell 提交信息 | 不支持 heredoc、`&&` | here-string / `-F 临时文件`；用 `;` + `$LASTEXITCODE` |
| `wsl -- bash -lc '多条命令'` | 外层引号被吞，报 `syntax error near unexpected token "("` | **把命令写成 .sh 脚本文件，再 `wsl -- bash /mnt/.../x.sh`** |
| WSL 里 `npm` 跑到 Windows 版 | PATH 互操作把 `/mnt/c/...` 的 npm 带进来，报 `WSL 1 is not supported` | 在 WSL 装原生 Node，并软链到 `/usr/local/bin` |
| 只配 `~/.bashrc` 的 PATH | 非登录 / 非交互 shell 找不到工具链 | 同时软链到 `/usr/local/bin`（默认 PATH 里就有） |
| 写凭据进文件 | 在对话/终端回显密码会留痕 | 用脚本从已有凭据处读出后**直接落盘**，只报告长度与是否含特殊字符 |
| 判断"是否已初始化" | 依赖 localStorage，换浏览器/清缓存就误判 | 服务端字段为权威 |
| 路由守卫引导页 | 探测接口失败被静默吞掉 → 误跳引导页 | 异常时放行，不误跳 |
| 改 CHECK 约束 | SQLite 不支持直接改 | 建新表 → 搬迁 → 删旧表 → 改名，并回填老数据 |
| 升级浮动标签 | `docker compose up -d` 不会拉新 `latest` | 先 `pull` 再 `up -d` |
| 跑服务的终端 | 被后续命令复用作掉，服务静默掉线 | 重启后必查健康状态 |
| 清理文件 | 直接删可能删到有用的（数据/备份/被引用的"疑似废弃"文件） | 先查引用（grep / `go:embed`）→ 分类清单 → 等确认 |
| 临时数据随手放 | 仓库里散落 `*.json`、`data2/`、误产出 `*.exe` | 一律归入 `_scratch/`；源码目录只放代码 |
