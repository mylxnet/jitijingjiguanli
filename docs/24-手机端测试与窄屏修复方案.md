## 1. 测试口径（复现方法）

- 环境：本机 `http://localhost:8080`（WSL `go run ./cmd/server`，已内嵌 v0.23.1 前端产物），调试库 org 6「朱潘村」。

- 覆盖：20 个页面/形态（全部路由 + 往来子页 + 三档视口）。
- 零写入核验：测毕 `GET /api/operation-logs` 仍为 **0 条**（写日志只由记账/划转/合同/应收/单位/分配及科目改名触发）。测试 iframe 已移除，页面恢复正常。

### 1.1 本方法的已知局限（下次别误读）

| 局限 | 影响 |
|---|---|
| 截图被拦（内置浏览器面板未打开，`visibilityState=hidden`） | **只有数字没有看图**：配色、留白、对齐、圆角裁切等视觉问题未覆盖 |
| 隐藏页面里 Vant 过渡的 `animationend` 不触发 | 弹窗会卡在 `*-enter-from`（被 transform 移到屏幕外）。量静止布局时剥离过渡类或临时 `transform:none`。**这是测试台副作用，不是应用缺陷** |
| 无触摸事件模拟 | 滑动手势、下拉刷新、软键盘顶起 bottom sheet 未测 |
| 非真机 | iOS Safari `100vh` 地址栏伸缩（`App.vue:58-93` 用 `min-height:100vh` + `padding-bottom:64px`）有被地址栏压住的经典风险，**本轮无法验证**；微信内置浏览器同样未测 |

## 3. 溢出宽度分布（决定媒体查询取值的实测依据）

| 宽度 | 汇总页 `.capital-cards` | 看板 `.donut-grid` |
|---|---|---|
| 430 | 行内 +36px（页面 +12） | 未犯病 |
| 390 | 行内 +36px（页面 +12~52※） | 0 |
| 375 | 行内 +91px（页面 +67） | 介于两者之间（未逐点定位） |
| 360 | 行内 +106px（页面 +82） | **+29px** |
| 320 | 行内 +146px（页面 +122） | **+69px** |

※ 同一 390 宽度两次取值不同（52 / 12），因第二次测时下钻弹层仍开着；趋势与结论不受影响。

**结论：汇总页在所有手机宽度上都溢出，桌面（≥800）完全不溢出；看板只在 ≤375px 犯病。** 所以修复的媒体查询上界取 `max-width:600px`（汇总）与 `max-width:375px`（看板），两者都 **低于桌面断点 800**，天然不重叠。

## 4. 逐条问题与"桌面端影响"结论

### P1-1 汇总页「资金构成」四卡撑破屏幕
- 现象：`.capital-card.total` 右边界 442 > 视口 390，页面横向可滚。
- 根因：`SummaryPage.vue:384-396` —— `.capital-cards{display:flex;gap:8px}` + `.capital-card{flex:1}`，而 flex 子项默认 `min-width:auto`，`¥ 3,586,260.00` 这类长金额的 min-content 撑住不允许收缩。
- 改法：`@media (max-width:600px){ .capital-card{min-width:0} .capital-card .card-value{font-size:12px} }`；若仍不够再上 `flex-wrap:wrap` 做 2×2。
- **桌面影响：无**（规则被媒体查询包住）。注意：`min-width:0` 若写成全局，理论上桌面也仅是"将来容器变窄时由溢出改为折行"，为绝对安全仍建议放媒体查询内。

### P1-2 看板「在外投资构成」环形卡在 ≤375px 溢出
- 根因：`Home.vue:360-365` —— `.donut-grid{grid-template-columns:1fr 1fr}`。320px 下每列约 140px，而 `.donut-svg{width:120px}` + `.donut-card{padding:14px}` 的 min-content = 148px，列被撑破。
- 改法：`@media (max-width:375px){ .donut-grid{grid-template-columns:1fr} }`（必要时给 `.donut-svg` 加 `max-width:100%`）。
- **桌面影响：无。** ⚠️ **禁止**图省事改成 `repeat(auto-fit, minmax(160px,1fr))` —— 桌面 `.home-page{max-width:none}`（`Home.vue:426-428`）下容器很宽，auto-fit 会把固定 2 列变成 3~4 列，**桌面版式当场被改**。

### P1-3 六处金额输入缺 `inputmode="decimal"`
- 现状：`RecordPopup.vue:37,79`、`PartiesList.vue:139-149`、`ReceivablesList.vue:41`、`AccrueWizard.vue:41`、`OnboardingPage.vue:550,568,577`、`CategoryPage.vue:100-102` 都写了 `inputmode="decimal"`；**缺**的是 `List.vue:106-117`（最小/最大金额两处）、`SettingsPage.vue:73-78`（银行存款期初）、`InvestmentsPage.vue:293,300,307,346`（532 分配三档 + 再投资金额）。
- 影响：iOS 上 `type="number"` 的数字键盘可能不带小数点，只能先输整数再改。
- 改法：补齐 `inputmode="decimal"`，与上面已有写法一致。
- **桌面影响：无**（纯触屏键盘提示属性）。

### P2-3 `RecordPopup` 的 `isDesktop` 断点不一致且非响应式
- 根因：`RecordPopup.vue:111` `const isDesktop = window.innerWidth > 768`，而全局断点是 `useScreen.ts` 的 **800**；且它是 setup 期一次性求值的普通常量（RecordPopup 是 `App.vue` 里的全局单例），**窗口尺寸变化后不更新**。
- 实测证据：横屏 844px 下点「记一笔」，弹窗 class 仍是 `van-popup--round van-popup--bottom`（应为桌面 `center` + `width:600px`）。
- 影响面：① 竖屏进应用后转横屏，记一笔形态停在旧值；② **769~799px** 区间出现"移动壳（有 BottomNav）+ 桌面弹窗（居中 600px）"混合形态。
- 改法：删本地 const，改用 `useScreen().isDesktop`；或保守版 —— 仅把 768 改成 800（一行），不做响应式。
- **桌面影响：≥800px 完全不变。** 变的是 769~799px 窄带；若做响应式，则"中途拖窗口/转屏会即时切换形态"属新增行为（是修复，但要知情）。

### P2-4 禁用了双指缩放
- 现状：`web/index.html:5` `user-scalable=no, maximum-scale=1`。
- 影响：叠加 P2-6 的小字号，弱视用户在手机上没有任何补偿手段（WCAG 1.4.4）。
- 改法：删 `maximum-scale`/`user-scalable`（保留 `width=device-width, initial-scale=1`）；若要兼顾 iOS 双击缩放误触，可只对输入框放开。
- **桌面影响：基本无**（桌面 Ctrl+ / 滚轮缩放不受该 meta 控制）。副作用：手机上双击页面会放大，可能误触。

### P2-5 `/reset-password` 显示了底部导航
- 根因：`App.vue:38` 免导航白名单只有 `/login`、`/register`、`/onboarding`，重置密码页漏了 → 移动端出现 BottomNav（点 tab 会被路由守卫弹回登录），页面还因 `.auth-wrap` 撑高而可滚（docH 908 > 844）。
- 改法（**保持桌面不变的那版**）：不要用"加进白名单"的省事做法 —— 那会连桌面 SideNav 一起去掉。改为仅在移动端隐藏：按路由给 `.bottomnav-mobile` 加 `@media (max-width:799px)` 下的 `display:none`。
- **桌面影响：无（按上述改法）。**

### P2-6 窄屏视觉密度（字号与触控目标）
实测各页 `<11px` 文本节点数 / 高 `<38px` 可点元素数：

| 页面 | `<11px` 文本 | 过小触控 | 典型 |
|---|---|---|---|
| `/categories` | **129** | **130** | `编辑` 30×24（320px 下 23×24）、`+二级` 36×24 |
| `/contacts/parties` | 34 | 31 | cl-tab 63×31 |
| `/contacts/contracts` | 17 | 27 | — |
| `/contacts/receivables/*` | 10~20 | 8~20 | — |
| `/`（看板） | 4 | 1 | `记一笔` 67×32 |
| `/settings` | 3 | 5 | `下载`/`恢复` 30×24 |
| `/transactions` | 2 | 2 | `筛选`/`导出` 34×24 |
| `/summary` | 2 | 3 | `<`/`>` 25×32 |
| `/login` | 0 | 1 | `忘记密码？` 65×19 |
| `/investment`、`/flow`、`/onboarding`、`/register` | 0~1 | 0~5 | il-tab / fl-tab 高 31 |

- 改法：只在 `@media (max-width:799px)` 内把最小字号抬到 ≥12px、把行内操作按钮的 padding 放大到 ≥40px 高；`.pl-table`（`PartiesList.vue:573` `min-width:820px`）在 ≤720px 改卡片式，**照抄 `ReceivablesList.vue:426-476` 的既有做法**（同模块已有窄屏卡片范式，保持一致）。
- **桌面影响：取决于写法。** 若直接调大全局基础字号/按钮尺寸 → 桌面表格行高变大、单屏可见行数变少，是用户能看出的变化，**必须先取得同意**；写成媒体查询则桌面不动。

## 7. 附：本轮取证脚本要点（下次复用）

```js
// 关键：同源 iframe 模拟视口；工具单次上限 15s，必须「一次调 2~3 页」
f = document.createElement('iframe')
f.style.cssText = 'position:fixed;left:0;top:0;width:390px;height:844px;border:0;z-index:99999;background:#fff'
// 隐藏宿主页应用实例，避免它自己占一份内存与轮询
document.getElementById('app').style.display = 'none'
f.contentWindow.location.href = '/#/login'   // 同域，HttpOnly 会话 Cookie 自动带上 → 已登录态
// 错误钩子（只在 iframe 首次加载后挂一次，hash 导航不换文档）
w.addEventListener('error', ...); w.addEventListener('unhandledrejection', ...)
// 溢出判定：b.right > innerWidth+1 且祖先链无 overflow-x:auto|scroll 且非 fixed → 真溢出
// 触控判定：matches('button,a,.van-button,.van-cell,[role=button],select') 且有文字且 rect.height < 38
// 弹窗静止布局：剥离 enter-from/enter-active，或临时注入 .van-popup{transform:none !important}
```

- 登录是 **HttpOnly Cookie**（`auth/middleware.go:21 c.Cookie(CookieName)`），不是 Bearer；`fetch` 不带 Authorization 也能 200，不要误判成"后端没鉴权"。
- 会话过期后 iframe 内会跳 `/login`，批量测前先探 `/api/me` 确认仍是 org 6。
