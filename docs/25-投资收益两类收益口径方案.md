# 25 · 投资收益两类收益口径方案（v2，已批准施工）

日期：2026-09-20　状态：**施工中**　影响版本：v0.24.0（待触发词确认）

## 1. 问题与取证

用户口径：**投资收益 = 长期投资收益 + 再投资收益**，投资管理页四个页签都要按"两项收益"来组织。

## 2. 目标口径（唯一权威）

**已收（实收）** = 该单位 `recv_kind ∈ (dividend, reinvest_dividend)` 应收单下的 `receipt(status='normal')` 核销合计：

- **含**现金收款（`method='cash'`）与抵销（`method='offset'`）
- **排除**坏账冲销（`method='writeoff'` 不是收到钱）与作废核销（`status='voided'`）
- **跨全部年度累计**（不看出账年份、不看应收单 open/closed）

数据源已在 v0.23.1 之后落地：`Party.dividendReceivedCents` / `Party.reinvestReceivedCents`（`ListParties` 聚合），前端 `ltReceivedTotal` / `riReceivedTotal` 已可用，**无需新增接口**。

三个口径必须分清（页面上会同时出现）：

| 口径 | 来源 | 用于 | 关系 |
|---|---|---|---|
| 已收收益 | `receipt` 聚合 | 投资收益页签展示、532 分配基数 | 权威 |
| 入账现金 | `投资收益` / `再投资收益` 科目余额 | **仅对账** | ≤ 已收（抵销不入账） |
| 年预期收益 | 单位 `expectedReturnCents` | 长期/再投资页签 | 应计，与实收无关 |

**科目只承担两件事**：① 存投出本金（长期/再投资页签金额列，代码注释已声明"科目余额为权威口径"）② 对账。不再作为收益展示源。

## 3. 已否决的替代路线

- **A 纯展示拆分**：不动科目 → 再投资收益继续污染再投资本金，账仍是错的。
- **B′（投资收益下加固定 L2「再投资收益」）**：迁移最省，但按单位维度丢失，且"再投资收益科目余额"取不出来 → 对账提示无依据。
- **三级科目**：schema 不支持（`level oneof 1 2`）。

## 4. 采纳方案

新增预置 L1 **「再投资收益」**（空容器，按单位名自动建同名 L2，与 `长期投资/再投资/投资收益` 同一惯例），入账容器改指它；页面与 532 全面改用「已收」口径。

### 4.1 后端
1. `migrations/020_reinvest_income_cat.sql`
   - L1 `sort_order ≥ 6` 整体后移一位，插入「再投资收益」于 `sort=6`（`preset=1, kind=equity, level=1`），逐组织 `NOT EXISTS` 守卫
   - 精确回填：`receipt(method='cash') ⨝ receivable(recv_kind='reinvest_dividend') → txn_id` 定位被错记的流水，先在「再投资收益」下补建同名 L2，再把 `txn.category_id` 挪过去（voided 流水一并挪，避免本金科目下留有收益痕迹）
2. `receivable/repo.go:838` — `reinvest_dividend` 容器 `"再投资"` → `"再投资收益"`
3. `auth/repo.go:seedPresetCategoriesTx` — 新组织预置同步为 9 个 L1

### 4.2 前端
4. `RecordPopup.vue:165` — `autoBuildL1` 按所选单位类型动态：`reinvest → 再投资收益`，否则 `投资收益`
5. `InvestmentsPage.vue` — 投资收益页签重做 + 532 基数换口径（见 §5）

### 4.3 周边
6. `server/mock.js` 与 `server/tests/{preset-onboarding,quick-biz-e2e,onboarding-flow}.js` — 硬编码"8 个 L1"改 9
7. `platform/migrate_test.go:39` — 迁移计数 19 → 20
8. `docs/04-dev-manual.md` — 预置科目表、`recvKindToL1` 映射、三口径对照、532 基数新口径

## 5. 投资管理页最终形态

| 页签 | 统计卡 | 表格 |
|---|---|---|
| 长期投资 | 投资笔数 / 投资总额 / 年预期收益 / **已收长期投资收益** / 平均收益率（现状保持） | 单位名称 / 投资金额 / 年收益率 / 年预期收益 / 已收 |
| 再投资 | 同上对称，「已收」即再投资收益；本金不再被收益虚减 | 同上 |
| **投资收益** | 收益合计 / 已收长期投资收益 / 已收再投资收益 / 已分配 / 未分配余额 | **行=往来单位（type ∈ invest/reinvest）**，列：单位名称 / 已收长期投资收益 / 已收再投资收益 / 合计 |
| 532 分配 | 「年度总收益」= **已收两类之和**，副标注明；弹窗提示改「已收收益合计（长期+再投资）」 | 分配明细与支出记录不变 |

投资收益页签不再读科目 children → 该页签彻底摆脱"同名挂接"。顶部加**对账提示**（仅差额≠0 时显示）：
`投资收益科目余额 ¥A 与已收 ¥B 差 ¥X —— 有 X 元收益系直接入账未挂应收，未计入可分配`。
CSV 导出同步 4 列。

迁移前基线（org 6，真实 `/api/categories` + `/api/parties`）：`再投资` L1 净余额 22,519,526；`再投资/羊鸡福` 1,733,948（期初 1,683,445 + 收益 50,503）；`投资收益` L1 1,100,000。

本库预期结果（迁移后，单位＝分）：
- 收益合计 ¥11,505.03 = 长期 ¥11,000.00 + 再投资 ¥505.03
- 532 可分配基数 ¥11,000.00 → **¥11,505.03**（未分配 +¥505.03）
- `再投资/羊鸡福` 回到 1,683,445（¥16,834.45），`再投资收益/羊鸡福` = 50,503，`再投资` L1 净余额回到 22,469,023（本金不再被收益虚增 ¥505.03）

## 7. 风险与遗留

1. **历史年度 532 数字会变**：基数换口径后未分配额上升（本库 +¥505.03）；已生成方案是 `total_income_cents` 快照不回改，仅新方案受影响。属纠错，需业务认可。
2. **直接入账未挂应收的收益不在「已收」内** → 靠对账提示兜底，不自动并入池子。
3. 长期/再投资页签金额仍靠**同名挂接**取科目余额（本金权威口径在科目）；根治需给 `category` 加 `party_id`，本方案不含。
4. 新 L1 是 `preset=1`（禁删禁改名），名称定了不可回退。
5. 生产库执行迁移前先跑只读核查、先 `mv` 备份库文件（**绝不删除**）。
6. 已定性但**本方案不修**：`再投资/甘肃琛兴科技`(id 130) 期初 420,000、投出 550,000 → 余额 −130,000，而页签金额列取 `Math.abs` 当成 +¥1,300 计入「再投资总额」。**负本金被绝对值洗白**是独立展示缺陷（`InvestmentsPage.vue:419`），与本次口径改造无关，单开一条处理。
7. 手机端 390/320px 新增两列后需复测；`docs/24` 那批窄屏问题仍为"暂不修改"。
