## 3. 逐条清单

### #1 `ContractsPage.vue:342` — mammoth 入参 `ArrayBufferLike`

- 现状：`const bytes = base64DataUrlToUint8(dataUrl)` → `mammoth.convertToHtml({ arrayBuffer: bytes.buffer })`
- 根因：`Uint8Array.buffer` 的类型是 `ArrayBufferLike`（可能是 `SharedArrayBuffer`），mammoth 只收 `ArrayBuffer`。
- 修法：`mammoth.convertToHtml({ arrayBuffer: bytes.buffer as ArrayBuffer })`
- 风险：无运行时变化；Word 预览为既有功能，改后需实机打开一个 `.docx` 附件确认预览正常。

### #2 `ContractsPage.vue:483` — `o.expiresAt` possibly undefined

- 现状：`contracts.value.some(o => o.partyId === c.partyId && o.expiresAt !== null && o.expiresAt > c.expiresAt!)`
- 根因：`expiresAt` 的类型是 `string | null | undefined`（可选字段），`!== null` 挡不住 `undefined`。
- 修法：把 `o.expiresAt !== null` 改成 `o.expiresAt != null`（一次挡住 `null` 与 `undefined`）。
- 口径确认：`!= null` 为**有意的宽松判空**（本项目 `expiresAt` 同时存在 null/undefined 两种空值来源），不要"顺手"改成 `!== null && !== undefined` 或 `!!o.expiresAt`（后者会把空串也判掉）。
- 风险：`undefined > string` 结果是 `false`，因此修复前后行为一致，属纯编译期收口。

### #3 `ReceivablesList.vue:83`（定义在 `:150`）— `van-tag` 的 `type`

- 现状：`const statusMeta: Record<string, { text: string; type: string }>`，模板 `:type="statusMeta[statusOf(r)].type"`
- 根因：`type` 被宽化成 `string`，而 `van-tag` 要的是字面量联合 `TagType`（`primary|success|danger|warning|default`）。
- 修法（在定义处单点收口，模板不动）：
  ```ts
  import type { TagProps } from 'vant'          // v4 稳定导出；若确认存在 TagType 也可直接用
  type TagType = TagProps['type']
  type RecvStatus = 'open' | 'partial' | 'closed' | 'writeoff'
  const statusOf = (r: Receivable): RecvStatus => …   // 给 :149 的函数补返回类型
  const statusMeta: Record<RecvStatus, { text: string; type: TagType }> = { … }  // 键从 string 收紧为联合
  ```
- 收益：`Record<RecvStatus, …>` 还能反向保证四种状态都有文案，漏一个就编译报错。
- 风险：`statusOf` 若将来新增状态，此处会强制补文案 —— 这是期望行为。

### #4 `InvestmentsPage.vue:678` — 局部 `Category` 缺 `kind`

- 现状：`findEquityCat()` 里 `l2.kind === 'equity'`（:678）报错；`l2` 的类型来自该文件 **`<script setup>` 内第 364 行的本地 `interface Category`**（只有 `id/name/level/parentId?/children?/balanceCents?`）。
- 根因：**本地重复声明的类型遮蔽了 `web/src/types/api.ts` 里同名且更完整的 `Category`**（那份有 `kind: 'equity' | 'asset'`）。
- 修法（两个方案，按红线「不扩大改动范围」优先取 A）：
  - **A 最小改**：给本地 `interface Category` 补 `kind?: 'equity' | 'asset'`。
  - **B 去重（后续单独做）**：删掉本地 `Category`，改为 `import type { Category } from '../../../types/api'`。注意共享类型还要求 `status/openingBalanceCents/sortOrder/createdAt` 等必填字段，直接切可能引出新一批报错 —— 需单独一轮，不混在本次修复里。
- 附带（同文件 :674）：`findEquityCat(name: string): any` 的返回 `any` 可一并收紧为 `Category | null`，属可选清理。

### #5 `InvestmentsPage.vue:801` — `/categories` 响应未标泛型

- 现状：`api.get('/categories')`，随后 `Array.isArray(cats) ? cats : (cats?.data || [])`
- 根因：`api.get<T>` 无默认泛型（`web/src/lib/http.ts:73-75`），省略 `T` 时编译器给不出结构，`cats.data` 就报「不存在于 `{}`」。同文件 `/parties`（:799）已经写了泛型，是漏了一个。
- 后端实测口径：`GET /api/categories` 走 `platform.SuccessResponse`（`server/internal/platform/error.go:45-47`），响应恒为 **`{ "data": Category[] }`**（树形数组）。
- 修法：与 `/parties` 保持一致的宽松写法
  ```ts
  api.get<{ data: Category[] } | Category[]>('/categories')
  ```
  现有 `Array.isArray(cats) ? cats : (cats?.data || [])` 保留，双兼容。

### #6 `OperationLogDialog.vue:109` — `res` 是 `unknown`

- 现状：`const res = await api.get('/operation-logs')` → `const data = res.data || res` → `logs.value = data.items || []`
- 根因：同 #5，泛型省略后 `res` 为 `unknown`，`.data` 访问不过。
- 后端实测口径：`GET /api/operation-logs` 注释即写明返回 `{ data: { items: OpLog[] } }`（`server/internal/changelog/handler.go:92`）。
- 修法：`const res = await api.get<{ data?: { items?: OpLog[] }; items?: OpLog[] }>('/operation-logs')`（保留 `res.data || res` 的双形状兜底，因为该接口历史上直出过裸数组）。
- 风险：清空日志按钮走同文件 `DELETE`，不在本次改动内。

### #7 · #8 `SummaryPage.vue:278-279` — **运行时真 bug：`range` 未定义**

- 现状（:269-284）：
  ```ts
  function goListWithFilter(t: Transaction) {
    if (!drillCat.value) return
    const y = drillYear.value
    const from = `${y}-01-01`
    const to = `${y}-12-31`
    void t
    router.push({ path: '/transactions', query: { from: range.from, to: range.to, categoryId: …, categoryName: … } })
  ```
- 根因：函数内**已经算好了局部 `from` / `to`**，query 里却写 `range.from` / `range.to`；该组件不存在 `range` 变量（全文件只有 `drillYear`），是从"日期区间"改版前遗留下来的死引用。`void t` 是为了压掉未使用参数告警而加的。
- 实际影响（不是"可能有影响"）：看板/汇总页点二级科目下钻 → 点某条流水跳流水页时，`router.push` 前就抛 `ReferenceError: range is not defined`，**跳转失败、筛选不生效**，控制台报错。
- 修法：`from, to`（直接用局部常量）
  ```ts
  query: { from, to, categoryId: String(drillCat.value.id), categoryName: drillCat.value.name }
  ```
- 接收端已核对：`web/src/features/transaction/List.vue:244-255` 正是读 `q.from / q.to / q.categoryId / q.categoryName`，参数名无需改。
- 语义依据：函数上方注释即写明「点某条流水跳转到流水页，并带**该科目 + 该年**筛选」，所以按"整年"用 `from/to` 符合原意；参数 `t` 修完后成为未使用参数（见 §6 待确认）。
