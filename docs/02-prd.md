## 1. 背景与目标

### 1.1 问题定义

为一个**集体经济组织**提供内部管理用的**收支台账**，替代目前无固定格式的 Excel，
让唯一的记账人能在手机上快速记一笔，并在月底一键导出可直接使用的收支汇总表。

### 1.2 现状与替代方案

| 现状 | 不足 |
|------|------|
| Excel 手工记账，无固定格式 | 录入麻烦（尤其手机上）、统计靠手搓、无历史留痕、易误改误删 |

**已评估并放弃的外部方案**：

| 方案 | 放弃理由 |
|------|----------|
| 手机记账 App（随手记等） | 数据在第三方服务器，用户不接受 |
| 现有开源方案（ezBookkeeping / Firefly III） | 用户选择从零自写，仅将其作为产品设计参照物 |
| 套用《农村集体经济组织会计制度》 | 用户明确为**内部管理台账**，不对外报送、不经审计、不受该制度约束 |

### 1.3 目标

| 目标 | 衡量指标 | 目标值 |
|------|----------|--------|
| 记账更快 | 手机上完成一笔记账的耗时 | ≤ 30 秒 |
| 出表不手搓 | 月底导出汇总表后需手工加工的步骤数 | 0 |
| 替代 Excel | 记账人是否持续使用、Excel 是否停用 | 连续使用满 1 个月 |

### 1.4 成功标准

**主标准**：记账人愿意持续使用，Excel 停用。

**可验证的替代指标**（用于 v0.1.0 验收）：
> 月底一键导出本月收支汇总表（xlsx），导出后**不需要任何手工加工**即可直接查看或打印。

⚠️ 隐含要求：导出的表格必须自带格式（表头、列宽、数字对齐、合计行）。
若导出后仍需手工调格式，则视为未达成。

### 1.5 明确不做（本期）

| 不做项 | 理由 |
|--------|------|
| 借贷平衡校验、期末结转、法定报表 | 不受会计制度约束 |
| 多币种与汇率 | 仅人民币 |
| 多人协作、共享账本、权限系统 | 单人使用 |
| 原生 App | 仅 Web / PWA |
| 图片附件与凭证扫描 | 未提出 |
| 计划交易（周期性自动记账） | 未提出 |
| 图表可视化 | 未提出，汇总以表格交付 |
| 预算与超支提醒 | 未提出 |
| 复式记账能力 | 见需求文档决策 D1 |
| 真离线记账 | 记账时均有网络；仅做「提交失败不丢草稿」 |
| 历史 Excel 数据导入 | 历史数据无固定格式，迁移价值低，从某时点起建新账 |

## 2. 用户与角色

### 2.1 角色定义

| 角色 | 描述 | 核心诉求 | 权限范围 |
|------|------|----------|----------|
| 记账人 | 唯一的系统使用者，负责全部收支录入与管理 | ① 快速记一笔 ② 随时查历史 ③ 月底出汇总表 | 全部数据，无角色区分 |

### 2.2 典型使用路径

**路径 1 · 日常随手记（最高频）**
1. 记账人在产生收支后，掏出手机，从主屏打开 PWA
2. 首屏直接是记账表单：选收/支 → 输金额 → 选二级科目 → 保存
3. 看到保存成功提示，表单重置为空白，可继续记下一笔

**路径 2 · 回看与核对**
1. 记账人在手机上打开流水列表
2. 用日期区间或科目筛选
3. 确认某段时间的收支情况

**路径 3 · 月底出表（验收路径）**
1. 记账人在桌面浏览器打开，进入汇总页
2. 选择本月，查看一级/二级分级小计
3. 点导出，选择 xlsx，得到可直接使用的月度收支汇总表

### 2.3 协作模式

**单人使用。** 无数据共享、无并发冲突、无权限分级。
登录仅用于防止局域网内他人误操作，不承担权限隔离职责。

## 3. 功能需求

### 3.1 功能优先级（MoSCoW）

| 优先级 | 功能 | 说明 |
|--------|------|------|
| **Must** | F1 记一笔 + 流水列表 + 按科目汇总 | 最小闭环，缺了等于项目失败 |
| **Must** | F2 一级科目自定义管理 | 没有科目就无法归类 |
| **Must** | F3 二级科目自定义管理 | 用户核心诉求「可定义的二级科目」 |
| **Must** | F4 筛选与搜索 | 查历史账必需 |
| **Must** | F5 导出 CSV + Excel | 达成成功标准的唯一出口 |
| Should | F6 变更历史查看 | 数据不可变策略（D0）的可见性出口 |
| Should | F7 定时自动备份 + 一键恢复 | 数据留存要求 |
| Could | F8 多月趋势对比 | 需求澄清中未纳入 Must |
| Won't | 图表可视化、预算提醒、附件上传、计划交易 | 本期明确不做 |

> Must = 5，与需求澄清第 2 轮一致，未发生范围蔓延。
> 评审期新增需求（D6 余额模型、D7 科目间转账、D8 余额表导出）以**扩展**方式并入既有 Must，
> 不新增计数：余额模型并入 F2/F3，转账发起并入 F2 配套，科目余额表并入 F5。

### 3.2 功能详情

#### F1. 记一笔 + 流水列表 + 按科目汇总

- **优先级**：Must
- **使用者**：记账人
- **前置条件**：已登录；至少存在一个启用中的一级科目及其下的二级科目
- **描述**：录入一笔**收支**，回看流水列表，按一级/二级科目分级查看区间小计，并查看资金构成
- **输入**：方向（收/支，表单顶部切换）；**字段自上而下：日期（默认今天）→ 摘要（可选）→ 二级科目（必选，仅列启用中的）→ 金额**（顺序为用户确认）
- **输出**：
  - 一条状态为「已录入」的收支流水
  - 按日期倒序的流水列表；**转账行也出现在本列表**（带「转账」标记，可按类型筛选）。转账的**发起**在科目管理页（见 F2 配套），此处仅查看与作废
  - 分级小计表格（**转账不计入收支**）
  - **资金构成**（见 D6）：银行存款余额 / 专项资金合计 / 未分配资金
  - **各科目余额**：期初 + 累计变动（收支与转账均计入，方向由科目类型决定）

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 金额 ≤ 0 或格式非法 | 拒绝保存，字段下方红字提示具体原因，保留已填内容 |
| 未选择二级科目 | 拒绝保存，提示「请选择科目」 |
| 日期为未来 | **允许**保存，但在字段旁显示黄色提示「日期晚于今天，确认无误吗？」 |
| 重复提交（连点/网络重试） | 提交中按钮禁用 + 后端幂等键校验，保证只产生一条 |
| 尚无任何科目 | 记账入口显示引导，跳转到科目管理先建科目 |
| 区间内无数据 | 空状态提示 + 「去记一笔」按钮，不显示空白表格 |
| 日期区间颠倒 | 自动交换起止日期并轻提示，不报错 |
| 已作废的流水 | 默认不计入汇总、不在列表显示；提供「显示已作废」开关 |
| **未分配资金为负** | 顶部橙色警告条：「专项资金合计（X）已超过银行存款余额（Y），请检查科目期初余额设置」。不阻止记账 |

- **验收标准**：
  - 手机上从打开到保存成功 ≤ 30 秒
  - 连续录入 20 笔后，按科目汇总结果与手工核算逐项一致
  - **资金构成恒等式成立**：`银行存款余额 − Σ(参与勾稽科目余额) = 未分配资金`，
    用 D6 验算表的 4 个步骤逐行核对

#### F2. 一级科目自定义管理

- **优先级**：Must
- **使用者**：记账人
- **前置条件**：已登录
- **描述**：新增、重命名、删除、停用一个一级科目；设定其余额类型与期初余额
- **输入**：科目名称、**余额类型（余粮型/花费型）**、**期初余额（可选，默认 0）**、**是否参与勾稽（仅余粮型可选）**
- **输出**：更新后的科目树，每行显示科目余额

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 同级重名 | 拒绝，提示「已存在同名科目」 |
| 删除**未被引用**的一级科目 | 允许，二次确认后删除 |
| 删除**已被引用**的一级科目 | **拒绝删除**，提示「该科目下仍有 N 笔流水，无法删除。你可以将其停用」 |
| 删除含二级科目的一级科目 | 拒绝，提示先处理其下的二级科目 |
| 停用已被引用的科目 | 允许，提示「停用后不再出现在记账选项，N 笔历史流水仍归属该科目」 |

- **验收标准**：建一个一级科目并停用，确认它不再出现在记账下拉框，但历史报表中仍可见

#### F2 配套 · 科目间转账（发起入口：科目管理页，见 D7）

> 用户明确要求转账**不放在记账页**（与收支概念混、界面丑），发起入口设于**科目管理**页。
> 转账记录仍在流水列表查看与作废（F1）。

- **优先级**：Must（D7 范围内）
- **使用者**：记账人
- **前置条件**：已登录；存在至少两个启用中的科目（一个可转出、至少一个可转入）
- **描述**：发起一笔「1 个转出科目 → N 个转入科目」的转账，用于专款调剂或期末结转
- **输入**：日期、**转出科目**（单选，显示当前余额，仅启用中）、**转入明细**（转入科目 + 金额，可加多行，**花费型科目不出现**）、摘要（提供快捷标签：年末结转 / 收益分配 / 专款调剂）
- **输出**：一笔状态为「正常」的转账（transfer + N 条 transfer_leg 原子写入）

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 转出总额 ≠ Σ转入总额 | 拒绝保存，提示差额；表单完整保留便于修正 |
| 转出金额 > 转出科目当前余额 | 拒绝保存，提示「余额不足，当前余额 ¥X」（R3） |
| 花费型科目作为转入方 | 下拉中不出现（R4）；接口层仍校验并返回 409 |
| 转入科目与转出科目相同 | 拒绝保存 |
| 停用中的科目 | 不出现在转出/转入下拉选项 |
| 提交中断（网络） | 单事务原子写入，不允许半笔转账；失败则整体回滚并提示重试 |

- **验收标准**：D7 验算表五步复现；转账行（①④⑤）不改变银行存款与未分配；转出超余额 / 花费型作转入方均被拒

#### F3. 二级科目自定义管理

- **优先级**：Must
- **使用者**：记账人
- **前置条件**：已登录；存在至少一个一级科目
- **描述**：在某个一级科目下新增、重命名、删除、停用二级科目；设定其余额类型与期初余额
- **输入**：科目名称、所属一级科目、**余额类型**、**期初余额（可选）**、**是否参与勾稽**
- **输出**：更新后的科目树，每行显示科目余额

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 同一一级科目下重名 | 拒绝 |
| 删除**未被引用**的二级科目 | 允许，二次确认后删除 |
| 删除**已被引用**的二级科目 | **拒绝删除**，提示可停用 |
| **改挂到另一个一级科目** | **不允许**，提示「科目不支持改挂。如需调整归属，请在目标科目下新建，并将原科目停用」 |
| 无一级科目时新增二级 | 拒绝，提示先建一级科目 |
| **花费型科目勾选「参与勾稽」** | **拒绝**，提示「只有余粮型科目能参与资金勾稽」并说明原因 |
| **修改已有流水的科目的期初余额** | 允许，但弹窗警告「该科目已有 N 笔流水，修改期初余额会改变其余额」+ 写入 change_log |
| **余额类型变更** | 已有流水时不允许变更类型；需先停用该科目并新建 |

- **验收标准**：尝试改挂被明确拒绝并给出替代操作指引；停用的二级科目不出现在记账下拉框；
  花费型科目无法勾选参与勾稽

#### F4. 筛选与搜索

- **优先级**：Must
- **使用者**：记账人
- **前置条件**：已登录；存在流水
- **描述**：按日期区间、科目、摘要关键字、金额范围过滤流水，并显示当前筛选条件下的小计
- **输入**：日期区间、科目（一级/二级）、摘要关键字、金额范围
- **输出**：过滤后的流水列表 + 当前筛选条件下的小计

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 无匹配结果 | 空状态 + 「清除筛选」按钮 |
| 日期区间颠倒 | 自动交换并提示 |
| 关键字无匹配 | 同上，空状态中回显当前筛选条件 |
| 金额范围非法（最小 > 最大） | 自动交换并提示 |

- **验收标准**：任意组合筛选后的小计，与筛选结果逐笔手工求和一致

#### F5. 导出 CSV + Excel

- **优先级**：Must
- **使用者**：记账人
- **前置条件**：已登录；当前筛选结果非空
- **描述**：将当前筛选条件下的流水、汇总表、科目余额表或它们的组合，导出为 CSV 或 xlsx
- **输入**：导出内容（流水 / 收支汇总 / **科目余额表** / 多选组合）、格式（CSV / xlsx）
- **科目余额表内容（D8）**：按一级科目分组，列出其下每个二级科目的**期初余额与当前余额**，一级科目给合计；
  表尾附银行存款余额 / 专项资金合计 / 未分配资金三行
- **输出**：下载文件

**异常与边界**：

| 异常情况 | 处理方式 |
|----------|----------|
| 当前结果为空 | 导出按钮禁用 + 提示「当前没有可导出的数据」 |
| 生成失败 | 提示失败原因 + 「重试」按钮，不清空当前筛选条件 |
| 数据量很大 | 流式生成，不限制跨度；前端显示生成中状态 |
| xlsx 格式要求 | 必须自带表头、列宽、数字右对齐、合计行加粗 —— 否则达不到成功标准 |

- **验收标准**：导出本月汇总 xlsx，用 Excel/WPS 打开后**无需任何手工加工**即可打印

#### F6. 变更历史查看（Should）

- **描述**：查看某条流水的历次修改记录（改前值、改后值、时间），以及作废/撤销作废的操作记录
- **验收标准**：修改一笔流水后，能在变更历史中看到改前改后的具体字段值

#### F7. 定时自动备份 + 一键恢复（Should）

- **描述**：系统定时生成 SQLite 一致性快照，支持在界面上选择某个备份点一键恢复
- **默认值**：每日 03:00 生成一次，保留最近 30 份；备份目录独立于数据目录，且**与数据不同盘**
- **验收标准**：手动触发一次备份，修改若干数据，一键恢复到备份点，数据完整回退

### 3.3 功能依赖

```
F2 一级科目管理 ─┐
                 ├─→ F1 记一笔 ─→ 流水列表 ─→ F4 筛选搜索 ─→ F5 导出
F3 二级科目管理 ─┘                    │
                                      └─→ 按科目汇总 ─────→ F5 导出

F6 变更历史 ←── 依赖 change_log 写入（F1 编辑/作废时产生）
F7 备份恢复 ←── 独立功能，无前置依赖
```

**硬前置**：F2 / F3 未完成，F1 就无法工作。因此 v0.1.0 必须同时包含科目管理的最小可用版本。

## 5. 数据模型

### 5.1 核心实体

#### user（记账人）
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INTEGER | 是 | 主键 |
| username | TEXT | 是 | 唯一，登录账号 |
| password_hash | TEXT | 是 | 口令哈希，禁止明文 |
| created_at | DATETIME | 是 | 创建时间 |

#### category（科目，严格两级）
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INTEGER | 是 | 主键 |
| name | TEXT | 是 | 科目名称 |
| level | INTEGER | 是 | 1 = 一级，2 = 二级 |

| **balance_type** | TEXT | 是 | `residual` 余粮型（收增支减）／`spending` 花费型（支增收减）。见 D6 |

> 已验算：花费型科目若参与勾稽，其正数余额会被二次扣减，导致「未分配资金」算错。

### 5.2 实体关系

```
category 1 ──< N category      （自关联：一级 → 二级）
category 1 ──< N transaction   （仅二级科目可被引用）
change_log  ·  ·  > transaction / category   （逻辑关联，无外键约束）
```

**级联策略**：

| 操作 | 策略 |
|------|------|
| 删除一级科目 | 若其下仍有二级科目 → 拒绝；若无 → 允许（且必须未被引用） |
| 删除二级科目 | 若已被 transaction 引用 → **拒绝**；未被引用 → 允许 |
| 删除 transaction | **任何情况都不允许物理删除**（见 D0） |
| 停用科目 | 不影响任何 transaction，历史归属保持不变 |

### 5.3 状态机

**category**：

```
active ──停用──> inactive ──重新启用──> active
   │
   └──（未被任何 transaction 引用时）──删除──> 物理删除
```

**transaction**：

```
        ┌──────────┐  编辑   ┌──────────────┐
        │  normal  │ ──────> │ normal(已改) │   每次编辑写 change_log
        └──────────┘         └──────────────┘
              │
              │ 作废（可撤销）
              ▼
        ┌──────────┐
        │  voided  │  不计入任何汇总；记录保留、可查
        └──────────┘

⚠️ 任何状态都不可物理删除
```

### 5.4 数据来源与留存

- **来源**：纯手工录入。无第三方接口、无文件导入。
- **留存**：数据永久保留，不自动清理。已作废的流水永久保留记录（仅不计入汇总）。
- **备份**：每日一次一致性快照，保留 30 份，与数据不同盘。

### 已识别技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SQLite 数据卷被误放到 NFS/SMB 挂载 | 文件锁不可靠，可能数据损坏 | 部署文档明确禁止；启动自检：检测数据目录是否在网络挂载上，是则启动失败并报错 |
| xlsx 生成内存峰值 | 容器 OOM | 使用 excelize 流式写入 API；数据量大时无需一次性载入 |
| Go 与 TS 两份类型定义不同步 | 改字段名时前后端不一致 | 后端接口变更时同步更新前端 `types/`；接口契约以本文档第 4.3 节为准 |
| NAS 盘故障 | 数据全丢 | 每日自动备份 + 一键恢复；**备份与数据不同盘** |
| Vite 8 / Rolldown 较新，部分插件可能未适配 | 构建失败 | v0.1.0 阶段即验证构建链路；若受阻，降级到 Vite 7 |
